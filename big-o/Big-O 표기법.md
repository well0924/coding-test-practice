### 1. 복잡도를 왜 따지는가

 복잡도는 알고리즘이 문제를 해결하는 과정에서 **입력 크기(N)에 따라 소모되는 자원**을 수치적으로 표현한 개념을 말합니다. 여기에서 자원이라 하는 것은 **시간(연산 횟수)과 공간(메모리 사용량)으로 나누어 생각하는 것을 말합니다. 

알고리즘의 성능은 특정 입력값 하나에 대한 실행 결과가 아니라, **입력 크기가 증가할 때 성능이 어떤 방식으로 변화하는지**를 기준으로 판단해야 합니다. 작은 입력에서는 차이가 없는 알고리즘이라도, 입력이 커질수록 실행 시간의 차이가 크게 벌어질 수 있기 때문입니다.

또한 실제 실행 시간은 CPU 성능, 메모리 크기, 운영체제, 프로그래밍 언어 및 런타임 환경에 따라 달라질 수 있습니다. 이러한 환경 의존성 때문에 실행 시간(ms)만으로 알고리즘의 성능을 일반화하여 비교하는 데에는 한계가 있습니다.

따라서 알고리즘의 성능은 **입력 크기에 따른 자원 사용량의 증가 경향**, 즉 복잡도를 기준으로 분석합니다. 복잡도에는 시간 복잡도와 공간 복잡도가 있습니다. 
### 2. 시간 복잡도와 공간 복잡도

###### 시간 복잡도

시간 복잡도는 알고리즘이 입력 크기(N)에 따라 수행하는 **연산 횟수의 증가량**을 나타냅니다.  
이는 실제 실행 시간과 달리, 실행 환경에 영향을 받지 않는 비교 기준으로 사용됩니다.

###### 공간 복잡도

공간 복잡도는 알고리즘이 실행되는 동안 추가로 사용하는 **메모리 공간의 증가량**을 의미합니다.  
입력 데이터를 저장하기 위한 공간 뿐만 아니라, 보조 배열이나 재귀 호출에 사용되는 스택 공간 등도 포함됩니다.

일반적으로 알고리즘 분석에서는 **시간 복잡도를 우선적으로 고려**합니다. 이는 실행 시간이 사용자 경험과 시스템 처리량에 직접적인 영향을 미치며, 시간 복잡도는 메모리 증설과 같은 방식으로 쉽게 보완할 수 없기 때문입니다. 

반면 공간 복잡도는 운영 환경에 따라 조정 가능한 경우가 많아, 메모리 제약이 있는 상황에서 함께 판단합니다.
### 3. 빅오(Big-O) 표기법

<img width="825" height="556" alt="Image" src="https://github.com/user-attachments/assets/b2a829b4-c184-48a4-9190-56598f5dd5bb" />

빅오(Big-O) 표기법은 알고리즘의 성능을 **입력 크기(N)가 증가할 때 수행되는 연산 횟수의 상한**으로 표현하는 방법입니다. 일반적으로 알고리즘의 **최악의 경우(Worst Case)를 기준으로 성능을 분석합니다.

일반적으로 빅오 표기법은 알고리즘의 **최악의 경우(Worst Case)를 기준으로 성능을 분석합니다. 이는 평균이나 최선의 경우보다, 항상 보장되는 성능 기준**이 시스템의 안정성과 예측 가능성 측면에서 더 중요하기 때문입니다.

 또한 빅오 표기법에서는 상수항과 계수를 제거하고, **입력 크기에 따른 성장률**만을 비교합니다.  
입력 크기가 충분히 커질수록 상수항의 영향은 미미해지며, 알고리즘의 성능 차이는 반복 구조에 의해 결정되기 때문입니다.

결과적으로 빅오 표기법의 핵심은 정확한 연산 횟수가 아니라,  **입력 크기 증가에 따라 성능이 어떤 속도로 증가하는지**를 비교하는 데 있습니다.

**자주 쓰는 시간 복잡도 유형과 코드**

시간 복잡도는 수식이 아니라 **코드 구조**로 판단한다. 아래는 자주 등장하는 시간 복잡도 유형과 그에 해당하는 대표적인 코드 형태이다.

#### **O(1)** – 상수 시간

입력 크기와 무관하게 항상 일정한 연산만 수행하는 경우이다.

`int getFirst(int[] arr) {     
	return arr[0]; 
 }`

- 반복문 없음 
- 항상 한 번의 연산  
    → **O(1)**

---
#### **O(log N)** – 로그 시간

입력을 반복적으로 절반씩 줄여가는 구조에서 나타난다.

`int binarySearch(int[] arr, int target) {     
	int left = 0, right = arr.length - 1;      
	
	while (left <= right) {         
		int mid = (left + right) / 2;          
		
		if (arr[mid] == target) return mid;         
		else if (arr[mid] < target) left = mid + 1;         
		else right = mid - 1;     
	}     
	
	return -1; 
 }`

- 반복문이 있지만
- 매 반복마다 탐색 범위가 절반으로 감소  
    → **O(log N)**
---

#### **O(N)** – 선형 시간

입력 크기 N에 비례하여 한 번 순회하는 구조이다.

`int sum(int[] arr) {     
	int total = 0;     
	
	for (int i = 0; i < arr.length; i++) {         
		total += arr[i];     
	}     	
	return total; 
 }`

- 단일 반복문
- 입력 크기만큼 반복  
    → **O(N)**
---
#### **O(N log N)** – 선형 로그 시간

입력을 분할하면서, 각 단계에서 선형 처리가 필요한 구조에서 나타난다.

`void mergeSort(int[] arr) {     
	if (arr.length <= 1) return;
	      
	int mid = arr.length / 2;     
	int[] left = Arrays.copyOfRange(arr, 0, mid);     
	int[] right = Arrays.copyOfRange(arr, mid, arr.length);      

	mergeSort(left);     
	mergeSort(right);     
	merge(arr, left, right); 
  }`

- 분할 단계: log N
- 각 단계에서 전체 병합 처리: N  
    → **O(N log N)**
    

---

#### **O(N²)** – 이차 시간

중첩 반복문 구조에서 발생하며, 입력이 커질수록 성능이 급격히 저하된다.

`void printAllPairs(int[] arr) {     

	for (int i = 0; i < arr.length; i++) {         
		for (int j = 0; j < arr.length; j++) {       
		       System.out.println(arr[i] + ", " + arr[j]);         
		 }     
	 } 
  }`

- 반복문 2중 중첩    
- N × N 번 수행  
    → **O(N²)**
---
#### **입력이 둘 이상일 때 (O(N + M), O(N × M))**

입력이 서로 독립적인 경우에는 각각의 크기를 분리해서 판단한다.

`void printTwoArrays(int[] a, int[] b) {     
	
	for (int i = 0; i < a.length; i++) {         
		System.out.println(a[i]);     
	}      
	
	for (int j = 0; j < b.length; j++) {         
		System.out.println(b[j]);     
	} 
 }`

- 첫 번째 반복문: N
- 두 번째 반복문: M  
    → **O(N + M)**

`void printCombinations(int[] a, int[] b) {     
	
	for (int i = 0; i < a.length; i++) {         
		for (int j = 0; j < b.length; j++) {             
			System.out.println(a[i] + ", " + b[j]);         
		 }     
	 } 
  }`

→ **O(N × M)**

---
#### **조건 분기 vs 반복**

조건문은 실행 경로를 나눌 뿐, 반복 횟수를 증가시키지 않는다.

`if (x > 0) {     
	doSomething(); 
 } else {     
	 doSomethingElse(); 
 }`

- 조건문 개수는 중요하지 않음
- **반복문의 횟수와 중첩 구조가 시간 복잡도를 결정**
