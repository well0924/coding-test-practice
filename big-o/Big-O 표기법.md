### 1. 복잡도를 왜 따지는가

 복잡도는 알고리즘이 문제를 해결하는 과정에서 **입력 크기(N)에 따라 소모되는 자원**을 수치적으로 표현한 개념을 말합니다. 여기에서 자원이라 하는 것은 **시간(연산 횟수)과 공간(메모리 사용량)으로 나누어 생각하는 것을 말합니다. 

알고리즘의 성능은 특정 입력값 하나에 대한 실행 결과가 아니라, **입력 크기가 증가할 때 성능이 어떤 방식으로 변화하는지**를 기준으로 판단해야 합니다. 작은 입력에서는 차이가 없는 알고리즘이라도, 입력이 커질수록 실행 시간의 차이가 크게 벌어질 수 있기 때문입니다.

또한 실제 실행 시간은 CPU 성능, 메모리 크기, 운영체제, 프로그래밍 언어 및 런타임 환경에 따라 달라질 수 있습니다. 이러한 환경 의존성 때문에 실행 시간(ms)만으로 알고리즘의 성능을 일반화하여 비교하는 데에는 한계가 있습니다.

따라서 알고리즘의 성능은 **입력 크기에 따른 자원 사용량의 증가 경향**, 즉 복잡도를 기준으로 분석합니다. 복잡도에는 시간 복잡도와 공간 복잡도가 있습니다. 
### 2. 시간 복잡도와 공간 복잡도

###### 시간 복잡도

시간 복잡도는 알고리즘이 입력 크기(N)에 따라 수행하는 **연산 횟수의 증가량**을 나타냅니다.  
이는 실제 실행 시간과 달리, 실행 환경에 영향을 받지 않는 비교 기준으로 사용됩니다.

###### 공간 복잡도

공간 복잡도는 알고리즘이 실행되는 동안 추가로 사용하는 **메모리 공간의 증가량**을 의미합니다.  
입력 데이터를 저장하기 위한 공간 뿐만 아니라, 보조 배열이나 재귀 호출에 사용되는 스택 공간 등도 포함됩니다.

일반적으로 알고리즘 분석에서는 **시간 복잡도를 우선적으로 고려**합니다. 이는 실행 시간이 사용자 경험과 시스템 처리량에 직접적인 영향을 미치며, 시간 복잡도는 메모리 증설과 같은 방식으로 쉽게 보완할 수 없기 때문입니다. 

반면 공간 복잡도는 운영 환경에 따라 조정 가능한 경우가 많아, 메모리 제약이 있는 상황에서 함께 판단합니다.
### 3. 빅오(Big-O) 표기법

<img width="825" height="556" alt="Image" src="https://github.com/user-attachments/assets/b2a829b4-c184-48a4-9190-56598f5dd5bb" />

빅오(Big-O) 표기법은 알고리즘의 성능을 **입력 크기(N)가 증가할 때 수행되는 연산 횟수의 상한**으로 표현하는 방법이다. 이는 알고리즘이 특정 입력에서 얼마나 빠르게 동작하는지를 설명하기보다는, 가장 불리한 입력이 주어졌을 때도 어느 수준까지 성능이 악화될 수 있는지를 판단하기 위한 기준입니다.

실제 문제 환경에서는 입력 데이터의 분포를 사전에 알 수 없으며, 항상 평균적이거나 최선의 경우만 발생한다고 가정할 수 없습니다. 따라서 알고리즘 분석에서는 가장 나쁜 상황에서도 반드시 보장되는 성능 기준이 필요하다.

이러한 이유로 빅오 표기법은 평균이나 최선의 경우가 아닌 **최악의 경우(Worst Case)**를 기준으로 성능을 분석한다. 이는 시스템의 안정성과 예측 가능성을 확보하기 위한 선택이며, 코딩 테스트나 실서비스 환경처럼 실패가 허용되지 않는 상황에서 알고리즘을 비교·선택하는 데 적합하다.

또한 빅오 표기법에서는 상수항과 계수를 제거하고 **입력 크기에 따른 성장률**만을 비교한다.  
입력 크기가 충분히 커질수록 상수항의 영향은 미미해지며, 알고리즘의 성능 차이는 반복 구조와 입력 감소 방식에 의해 결정되기 때문이다.

결과적으로 빅오 표기법의 핵심은 정확한 연산 횟수를 계산하는 것이 아니라, **입력 크기가 증가할 때 성능이 어느 속도로 악화되는지를 미리 판단하는 데 있다.**

**3-1.자주 쓰는 시간 복잡도 유형과 코드**

시간 복잡도는 수식이 아니라 **코드 구조**로 판단합니다. 아래는 자주 등장하는 시간 복잡도 유형과 그에 해당하는 대표적인 코드 형태입니다.

#### **O(1)** – 상수 시간

입력 크기와 무관하게 항상 일정한 연산만 수행하는 경우입니다.

`int getFirst(int[] arr) {     
	return arr[0]; 
 }`

이 함수는 입력 배열의 크기와 관계없이  항상 인덱스 0에 한 번 접근합니다.

연산 횟수는 입력 크기 N과 무관하게 일정하므로 입력 크기가 증가해도 수행 시간은 변하지 않습니다.

따라서 시간 복잡도는 O(1)입니다.

---
#### **O(log N)** – 로그 시간

입력을 반복적으로 절반씩 줄여가는 구조에서 나타난다.

`int binarySearch(int[] arr, int target) {     
	int left = 0, right = arr.length - 1;      
	
	while (left <= right) {         
		int mid = (left + right) / 2;          
		
		if (arr[mid] == target) return mid;         
		else if (arr[mid] < target) left = mid + 1;         
		else right = mid - 1;     
	}     
	
	return -1; 
 }`

- 반복문이 있지만
- 매 반복마다 탐색 범위가 절반으로 감소  
    → **O(log N)**

이진 탐색에서는 반복이 한 번 실행될 때마다 탐색 대상이 되는 데이터의 범위가 절반으로 줄어듭니다.

초기 입력 크기가 N일 때 N → N/2 → N/4 → … → 1 이 될 때까지 반복되며, 이 과정이 수행되는 횟수는 log₂N에 비례합니다.

따라서 반복문이 존재하더라도 입력 크기 증가에 따라 반복 횟수가 로그 형태로 증가하므로  
시간 복잡도는 **O(log N)** 입니다.

---

#### **O(N)** – 선형 시간

입력 크기 N에 비례하여 한 번 순회하는 구조이다.

`int sum(int[] arr) {     
	int total = 0;     
	
	for (int i = 0; i < arr.length; i++) {         
		total += arr[i];     
	}     	
	return total; 
 }`

- 단일 반복문
- 입력 크기만큼 반복  
    → **O(N)**

이 반복문은 배열의 모든 요소를 처음부터 끝까지 정확히 한 번씩 방문합니다.

입력 크기가 N일 때 반복문은 항상 N번 실행되며, 입력 크기가 두 배가 되면 연산 횟수도 두 배가 됩니다.

따라서 연산 횟수가 입력 크기에 비례하여 증가하므로 시간 복잡도는 **O(N)** 이다.

---
#### **O(N log N)** – 선형 로그 시간

입력을 분할하면서, 각 단계에서 선형 처리가 필요한 구조에서 나타납니다. 

`void mergeSort(int[] arr) {     
	if (arr.length <= 1) return;
	      
	int mid = arr.length / 2;     
	int[] left = Arrays.copyOfRange(arr, 0, mid);     
	int[] right = Arrays.copyOfRange(arr, mid, arr.length);      

	mergeSort(left);     
	mergeSort(right);     
	merge(arr, left, right); 
  }`

- 분할 단계: log N
- 각 단계에서 전체 병합 처리: N  
    → **O(N log N)**

병합 정렬은 배열을 절반씩 분할하며 재귀 호출을 수행합니다. 이 분할 깊이는 log N 수준입니다.

각 분할 단계에서 모든 원소를 대상으로 병합 작업이 수행되므로 각 단계마다 N에 비례하는 연산이 발생합니다.

따라서 전체 연산량은 N × log N 형태가 되어 시간 복잡도는 **O(N log N)** 입니다.

---
#### **O(N²)** – 이차 시간

중첩 반복문 구조에서 발생하며, 입력이 커질수록 성능이 급격히 저하됩니다.

`void printAllPairs(int[] arr) {     

	for (int i = 0; i < arr.length; i++) {         
		for (int j = 0; j < arr.length; j++) {       
		       System.out.println(arr[i] + ", " + arr[j]);         
		 }     
	 } 
  }`

- 반복문 2중 중첩    
- N × N 번 수행  
    → **O(N²)**

외부 반복문이 N번 실행되고, 각 반복마다 내부 반복문이 다시 N번 실행됩니다.

따라서 전체 연산 횟수는 N × N 형태로 증가하며, 입력 크기가 커질수록 실행 시간이 급격히 증가합니다. 이러한 구조는 입력 크기 제한이 큰 문제에서는 **시간 초과가 발생할 가능성**이 높습니다. 

---
#### **입력이 둘 이상일 때 (O(N + M), O(N × M))**

입력이 서로 독립적인 경우에는 각각의 크기를 분리해서 판단합니다.

`void printTwoArrays(int[] a, int[] b) {     
	
	for (int i = 0; i < a.length; i++) {         
		System.out.println(a[i]);     
	}      
	
	for (int j = 0; j < b.length; j++) {         
		System.out.println(b[j]);     
	} 
 }`

- 첫 번째 반복문: N
- 두 번째 반복문: M  
  → **O(N + M)**

두 반복문은 서로 독립적으로 실행되며, 전체 연산 횟수는 각각의 반복 횟수를 더한 값이 됩니다.

`void printCombinations(int[] a, int[] b) {     
	
	for (int i = 0; i < a.length; i++) {         
		for (int j = 0; j < b.length; j++) {             
			System.out.println(a[i] + ", " + b[j]);         
		 }     
	 } 
  }`

→ **O(N × M)**

이 경우 외부 반복문이 N번 실행되고, 각 반복마다 내부 반복문이 M번 실행되므로 전체 연산 횟수는 곱셈 구조가 됩니다.

---
#### **조건 분기 vs 반복**

조건문은 실행 경로를 나눌 뿐, 반복 횟수를 증가시키지 않습니다.

`if (x > 0) {     
   doSomething(); 
 } else {     
   doSomethingElse(); 
 }`

- 조건문 개수는 중요하지 않는다.
- **반복문의 횟수와 중첩 구조가 시간 복잡도를 결정한다.**

조건문은 참·거짓을 한 번 판단하는 단일 연산이므로 입력 크기 N이 증가하더라도 반복 실행되지 않습니다.

반면 반복문은 입력 크기에 따라 실행 횟수가 증가하며, 중첩될 경우 연산 횟수가 누적되어 급격히 증가합니다.

따라서 시간 복잡도는 조건문의 개수가 아니라 **반복문의 최대 실행 횟수와 중첩 깊이**를 기준으로 판단합니다.

---
### 4. 코딩 테스트에서 시간 복잡도 판단하는 방법

코딩 테스트에서는 문제마다 입력 크기 제한(N)이 명시되어 있으며, 이 제한을 기준으로 통과 가능한 시간 복잡도의 범위를 먼저 추정해야 합니다.

따라서 문제를 풀기 전에  
1) 입력 크기 제한 확인  
2) 허용 가능한 시간 복잡도 추정  
3) 코드 구조 선택  
의 순서로 접근합니다.

| 입력 크기 N       | 일반적으로 허용되는 시간 복잡도 |
| ------------- | ----------------- |
| N ≤ 10        | O(N!), O(2^N)     |
| N ≤ 100       | O(N³)             |
| N ≤ 1,000     | O(N²)             |
| N ≤ 100,000   | O(N log N), O(N)  |
| N ≤ 1,000,000 | O(N)              |

위의 표를 보면 알듯이 입력 크기가 커질수록 중첩 반복문 구조(O(N²) 이상)는 시간 초과 가능성이 급격히 증가합니다. 

예를 들어 입력 크기 N ≤ 100,000 인 문제가 주어졌을 때, 이중 반복문을 사용하는 O(N²) 알고리즘은 최악의 경우 약 10¹⁰번의 연산이 발생하므로 현실적으로 시간 제한을 초과합니다.

따라서 이 경우에는 정렬 + 단일 순회(O(N log N)) 또는 해시 자료구조를 활용한 단일 반복(O(N))  과 같은 구조를 우선적으로 고려해야 합니다.
