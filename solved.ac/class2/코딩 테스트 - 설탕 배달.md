2.문제 해결 과정

![Image](https://github.com/user-attachments/assets/2c164fc1-e05c-4319-b899-627c4a2c44b2)

문제의 요구 사항은 아래와 같습니다. 

1. 3키로, 5키로 봉지를 조합을 해서 N킬로그램을 배달해야 된다.
2. 예를 들어서 18 -> 3 * 6이 아닌 5 * 3+3 * 1 개면 더 적은 개수로 배달이 가능하다.
3. 봉지의 최소 개수를 출력 ->입력값의 N킬로그램을 만들 수 없다면 -1로 출력하기. 

이 문제에서 핵심은 **봉지 개수의 최소값을 보장하는 선택 기준**이 존재하는지 여부가 관건이다.

이 문제의 조건을 보면 다음과 같은 특징이 있다.
- 사용할 수 있는 봉지는 **3kg, 5kg 두 종류**
- 목표는 **정확히 Nkg을 만들면서 봉지 개수를 최소화**
- 봉지 개수 최소화 = **한 번에 더 많이 담을수록 유리**

즉, **같은 무게를 만들 수 있다면 5kg 봉지를 최대한 사용하는 것이 항상 이득**이라는 점입니다.

여기서 중요한 점은 **5kg 봉지를 최대한 사용한 선택이 이후의 선택 가능성을 깨뜨리지 않는다**. 라는 사실을 알 수 있습니다. 

왜냐하면 
- 5kg로 나눈 나머지는 `0, 1, 2, 3, 4`
- 이 중 **3으로 보정 가능한 경우(3, 6, 9 …)** 가 반복적으로 등장한다
- 따라서 `5kg을 하나 줄이고 3kg을 하나 추가` 하는 방식으로 항상 다음 상태를 검증할 수 있습니다.

이 구조는 현재 단계에서 최선의 선택(5kg 우선)이 전체 최적해(최소 봉지 개수)로 이어진다는 점에서 이 문제는 **그리디** 접근이 타당하다고 보았습니다.

다음으로 떠오른 풀이법은 아래와 같습니다. 

- N을 우선적으로 5키로로 최대한 나누기. 
- 그리고 여기에서 나머지 값을 3으로 나누기. 
- 나누어지면 정답이고 만약에 아닌 경우에는 5키로를 좀 줄이고 다시 남은 무게를 확인하기.
- N이 0보다 작아질 때까지 반복하기. 
- 최후에 안되면 -1로 끝나기. 

위의 내용을 토대로 한 흐름도와 제출한 코드는 아래와 같습니다.

<img width="1725" height="766" alt="Image" src="https://github.com/user-attachments/assets/c9fea070-fe84-493d-a7a5-357942c7037c" />

```
import java.io.BufferedReader;
import java.io.InputStreamReader;
import java.io.IOException;

public class Main {
    public static void main(String[] args) throws Exception {
        BufferedReader br = new BufferedReader(new InputStreamReader(System.in));
        int input = Integer.parseInt(br.readLine());

        int count = 0;

        while (input >= 0) {
            if (input % 5 == 0) {
                count += input / 5;
                System.out.println(count);
                return;
            }
            input -= 3;
            count++;
        }

        System.out.println(-1);
    }
}
```

3.타인 코드 분석 

문제를 제출 후 타인이 제출한 코드를 관찰하면서 몇 가지의 유형으로 푼 것을 알 수 있었습니다.

종류는 아래와 같았습니다. 
- **DP(Dynamic Programming)을 활용한 문제 풀이.**
- **나머지 기반의 문제 풀이**
- **사전 초기화 + 규칙 기반**
- **그리디를 사용한 문제 풀이**

3-1. DP를 활용한 문제 풀이

<img width="973" height="665" alt="Image" src="https://github.com/user-attachments/assets/6c27447b-d614-4c5e-9834-c42d98205fa6" />

이 방식은 DP를 사용해서 문제를 푼 방식입니다. 

특징
- `dp[i]`를 ikg을 만들기 위한 최소 봉지 개수로 정의
- 문제의 최대 입력값이 5000이므로, DP 배열을 **절대 나올 수 없는 큰 값(5001)**으로 초기화하여 만들 수 없는 상태를 구분하도록 했다.
- dp[3],dp[5] 를 1로 최솟값으로 정한 다음에 6 이상부터는 dp[i] = min(dp[i-3], dp[i-5]) + 1 형태로 최소값을 갱신한다.
- 최종적으로 범위를 넘어가면 -1을 출력 그렇지 않으면 반복문에서 연산한 배열의 수를 출력을 합니다.

3-2.나머지 기반의 문제 풀이

<img width="981" height="843" alt="Image" src="https://github.com/user-attachments/assets/e864c37e-ce14-4f3a-9649-b003f31f6181" />

```
switch (n % 5) {
    case 0: return n / 5;
    case 1: return 2 + (n - 6) / 5;
    case 2: return 4 + (n - 12) / 5;
    case 3: return 1 + (n - 3) / 5;
    case 4: return 3 + (n - 9) / 5;
}
```
이 풀이는 **N을 5로 나눈 나머지에 따라 최소 봉지 개수를 수식으로 계산하는 방식**입니다.  

**특징**
- `n % 5` 값에 따라 최소 조합을 미리 정리해 분기 처리
- 반복문 없이 O(1) 시간 복잡도로 계산 가능
- 사전 패턴 분석이 필수적이며, 문제 조건에 강하게 의존함

3-3.사전 초기화 + 규칙 기반의 문제 풀이

<img width="966" height="902" alt="Image" src="https://github.com/user-attachments/assets/e43481f3-b47a-4801-8b83-2a5eaa783848" />

```
int[] initArr = {0,0,0,1,0,1,2,0,2,3,2,3,3,4,3,4};
```

이 방식은 **작은 입력 구간의 결과를 미리 계산해 두고**, 그 이후 구간은 일정한 규칙으로 확장하는 방식입니다. 

**특징**
- 15kg 이하 결과를 배열로 하드코딩
- 이후 구간은 `+5kg → +1봉지` 규칙으로 확장
- 반복 횟수가 매우 적고 연산이 단순함
- 패턴을 설명하지 못하면 설득력이 떨어질 수 있음

3-4.그리디를 사용한 문제 풀이

<img width="1130" height="903" alt="Image" src="https://github.com/user-attachments/assets/b529bbec-5fed-4252-b32a-e4e57e0f930c" />

이 방식은 **5kg 봉지를 최대한 사용하고**, 나누어지지 않는 경우에만 **3kg 봉지로 보정하는 방식**입니다. 
###### 특징
- 반복 구조가 단순함
- 문제 조건과 구현 로직이 직관적으로 연결됨
- 별도의 상태 저장이 필요 없음
###### 3-5. 나에게 필요한 것 정리 

여러 풀이 방식을 비교해본 결과, 문제 해결에 있어 **가장 중요한 것은 알고리즘 종류 자체가 아니라 문제 구조에 맞는 선택 기준을 세우는 것**임을 알 수 있었습니다.

- DP는 모든 경우를 계산하므로 안정적인 해결 방법이지만, 문제 구조가 단순한 경우(3kg,5kg을 사용하는 경우)에는 불필요하게 복잡해질 수 있습니다.
- 나머지 기반 풀이와 사전 초기화 방식은 빠르지만, 사전 분석이 필요하고 문제 조건에 강하게 의존합니다.
- 반면 그리디 방식은 **선택 기준이 명확하고**, 문제 조건과 구현 로직이 자연스럽게 연결됩니다.

따라서 이 문제에서는 **복잡한 상태를 저장하거나 모든 경우를 계산하기보다, 현재 단계에서의 최선의 선택이 전체 최적해로 이어지는지를 먼저 판단하는 것이 더 중요하다고 판단했습니다.**

4.소감

이 문제를 통해 알고리즘의 종류를 먼저 고르는 것보다, **문제 구조에서 선택 기준이 성립하는지를 판단하는 과정이 더 중요하다는 점을 확인했습니다.**

DP, 나머지 기반, 사전 초기화 등 다양한 풀이가 가능했지만, 본 문제에서는 **현재 단계의 최선의 선택이 전체 최적해로 이어지는지**를 판단하는 것이 핵심이었습니다.

이후 유사한 최소값 문제를 마주했을 때에도 먼저 그리디 선택이 가능한 구조인지부터 검토해볼 것입니다.
