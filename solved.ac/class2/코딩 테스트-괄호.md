문제의 요구 사항은 다음과 같습니다.

1.'('랑 ')'로 이루어져 있는 문자열
2.괄호의 문자열이 올바르게 이루어져 있는 문자열
3."( )" 로 이루어져 있는게 VPS 
4.(x)도 문자열 / xy도 VPS  -> 즉 괄호 안에 괄호도 vps로 인정
5.괄호가 어긋나면 vps가 아님.
6.출력은 vps면 yes 아니면 no 임. -> 입력값 N만큼 괄호 문자열을 입력 -> 입력한 문자열을 가지고 판단을 한다. 
7.입력값 N의 경우에는 2이상 50이하 즉 1이상 25이하 이므로 빅오 표기법으로 보면  시간 복잡도(O(N))으로 로직을 구현을 하는데 있어서는 문제가 되진 않음. 

위의 요구사항을 토대로 요점을 말하면 **괄호 문자열을 입력을 했을때 괄호와 괄호안의 괄호를 어떻게 체크를 할 것인가?** 입니다.

다음은 문제의 예시입니다. 

```
6
(())())  
(((()())()
(()())((()))
((()()(()))(((())))()
()()()()(()()())()
(()((())()(

3
((
))
())(()

```

위의 예시를 보고 입력값의 패턴을 분석하면 다음과 같습니다. 

1.'('으로 먼저 시작 할것 -> 왜냐하면 ')'으로 시작을 하면 올바른 괄호가 안된다.
2.괄호의 순서는 '('이 먼저 그 다음은 ')'이 짝을 이룰 것 그리고  문자열 중간에는 '(' 의 갯수가 문자열에서 ')'보다 많을것 
3.최종적으로는 모든 문자를 처리한 뒤 '('와')'의 갯수가 같을것.

이를 종합해 보면 다음과 같은 결론이 나옵니다.

1. 괄호 문자열은 가장 최근에 열린 괄호가 가장 먼저 닫혀야 하는 구조를 가진다.
2. 현재 문자열을 검사할 때 직전에 처리한 '('의 상태를 유지해야 하며, **이를 위해 LIFO 특성을 가진 스택을 사용하기로 했다**. ')'가 등장했을 때 스택이 비어 있다면 즉시 유효하지 않은 상태로 판단할 수 있어 중간 실패를 빠르게 처리할 수 있다.

제가 생각한 최초의 의사 코드는 다음과 같습니다.

1.최초의 숫자 (괄호 문자열을 사용할 횟수)를 입력
2.사용할 횟수(1번의 입력값)만큼 반복문을 돌린다. 이때 스택과 중간 상태가 유효한 지의 변수를 선언을 한다.(스택 라이브러리 + boolean 타입의 isValid)   
3.2번 반복문 안에 괄호 문자열을 입력을 한다. 
4.괄호 문자열을 char타입의 배열로 변환을 한다.
5.4번 배열의 수만큼 2번 반복문 안에 반복문을 돌린다.
6.내부 반복문에서 조건문을 걸고 배열의 인덱스가 '('이면 스택에서 push를 하고 ')'이면 pop을 한다.
7.')'조건에서 조건이 깨지면 유효 변수를 false로 하고  break를 건다.
8.외부 반복문 안에서 최종적으로 유효 변수와 스택의 isEmpty를 조건문으로 걸고 해당하면 YES를 아니면 NO를 출력한다.

제출하기전 작성한 코드와 로직 플로우는 다음과 같습니다.

<img width="1777" height="2102" alt="Image" src="https://github.com/user-attachments/assets/4ed49238-e3cb-49fd-9f83-086a62d792c3" />

```
public static void main(String[] args) throws IOException {

		BufferedReader br = new BufferedReader(new InputStreamReader(System.in));

		//초기 입력수 
		int n = Integer.parseInt(br.readLine());

		for(int i =0; i< n; i++) {
			// 괄호 입력값 넣기.
			String input = br.readLine();
			Stack<Character>check = new Stack<Character>();
			boolean isValid = true;

			//반복문을 돌리면서 (면 push )면 pop
			//연산을 하면 중간에 음수가 나오면 x
			for (char c : input.toCharArray()) {
		        if (c == '(') {
		            check.push(c);
		        } else {
		            if (check.isEmpty()) {
		                isValid = false;
		                break;
		            }
		            check.pop();
		        }
		    }

			if(isValid && check.isEmpty()) {
				System.out.println("YES");
			} else {
				System.out.println("NO");
			}
		}
	}
```

다음으로는 작성한 코드에서 문제의 테스트 케이스를 고려해 보겠습니다. 

1.올바른 괄호 

요구 사항에서 제시한 형태입니다. 

- **입력:** `(())()`
- **설명:** 모든 열린 괄호가 제짝을 찾아 닫히고, 마지막에 스택이 비어 있습니다.

2.열린 괄호가 더 많은 경우 

루프가 끝났을 때 isValid는 true지만 스택이 비어있지 않은 케이스입니다.

- **입력예:** `(()` 또는 `((()`
- **설명:** 루프 종료 후 스택에 `(`가 남아 있습니다. `check.isEmpty()` 조건에 의해 **NO**가 출력됩니다.

3.닫힌 괄호가 먼저 나오거나 더 많은 경우 

루프 중간에 스택이 비어있는데 )가 들어오는 케이스입니다. 

- **입력예:** `())(` 또는 `)))`
- **설명:** 세 번째 글자 )에서 check.isEmpty()가 참이 되어 isValid = false가 되고 즉시 break 됩니다.

4.순서가 뒤섞인 경우

개수는 맞지만 짝이 맞지 않는 케이스입니다.

- **입력예:** `)(`
- **설명:** 시작부터 `)`가 나오므로 바로 `isValid = false`가 됩니다.

5.최소/최대 길이 케이스

- **최소:** `()` (YES) / `(` (NO) / `)` (NO)
- **최대:** 문제 제한인 길이 50의 문자열 (예: `((...))` 25쌍)

**3.타인 코드 분석 및 적용할 부분 분석**

문제를  맞춘 다음 타인의 코드를 분석을 하기 위해서 1~6페이지 까지의 정답 코드를 보았는데 대표적인 코드를 3개를 봤습니다. 유형은 아래와 같습니다. 

- ArrayDeque를 사용한 풀이
- 카운트를 사용한 풀이
- 카운트 + 유효성 검사를 추가한 풀이

3-1. ArrayDeque를 사용한 풀이

<img width="717" height="873" alt="Image" src="https://github.com/user-attachments/assets/b1724f9a-eef5-43f2-b591-effa60665d76" />

이 코드의 특징은 다음과 같습니다.
- `Stack` 클래스 대신 `ArrayDeque<Character>` 사용
- `offer`, `pollLast`, `peekLast`로 **스택 동작 직접 구현**
- 잘못된 괄호도 **스택에 계속 쌓아서** 최종 `isEmpty()`로 판정

3-2. 카운트 기반의 풀이

<img width="822" height="756" alt="Image" src="https://github.com/user-attachments/assets/73f022cb-7d73-47ff-b384-41f64aadbb64" />

이 코드의 특징은 다음과  같습니다. 
- 스택을 사용을 하지  않고 int answer 하나로 상태를 관리를 한다는 점.
- 괄호를 숫자로 카운팅 ( -> +1, ) -> -1 로 정해서 처리
- 중간에 `answer == 0` 상태에서 `)` 나오면 즉시 실패

3-3. 카운트 + 유효성 검사를 추가한 풀이

<img width="706" height="900" alt="Image" src="https://github.com/user-attachments/assets/99f76d4c-16b2-418c-885b-b2494145cc7c" />

이 코드의 특징은 다음과 같습니다.
- `isValid()`로 로직 분리
- 사전 조건 검사를 통해서 길이가 홀수인지 그리고 첫 글자가 )인지 마지막 글자가 (인지를 확인검사
- 그 후 괄호의 카운트를 검사

3-4. 예시에서 얻은 내용

먼저, ArrayDeque를 사용한 풀이는 스택 자료구조의 개념을 가장 직관적으로 표현한 방식이었다.  여는 괄호는 push, 닫는 괄호는 pop이라는 구조가 VPS 정의와 정확히 대응되며, 괄호의 중첩 구조를 이해하기에 가장 명확한 구현이라는 장점이 있다.

카운트 기반 풀이는 이러한 점을 단순화한 방식으로, 스택 대신 정수 하나로 열린 괄호의 개수를 관리하여 **공간 복잡도를 O(1)**로 줄였다. 중간에 카운트가 음수가 되는 순간 즉시 실패 처리함으로써, 문제의 핵심 조건을 가장 간결하게 구현한 방식이라고 볼 수 있다.

마지막으로, 카운트 방식에 **사전 유효성 검사와 로직 분리**를 추가한 풀이는 단순한 문제 풀이를 넘어 검증 로직의 안정성과 가독성을 고려한 구현이었다. 길이가 홀수인 경우, 시작이 `)`이거나 끝이 `(`인 경우를 미리 걸러냄으로써 불필요한 연산을 줄이고, 검증 책임을 `isValid()` 함수로 분리해 코드 구조를 명확히 했다.



**4.소감**

이번 문제를 통해 단순히 “괄호 문제를 풀었다”는 것보다, **같은 문제를 다양한 관점에서 바라보고 더 나은 방향으로 개선해 나갈 수 있다는 점을 계속해서 연습하고 있는 중입니다.**

처음에는 스택을 사용한 방식으로 문제를 해결했는데, 이는 괄호의 중첩 구조를 가장 직관적으로 표현할 수 있는 방법이었고 문제의 요구 사항을 충족하는데 충분히 타당한 접근이라고 판단했습니다.

타인의 코드를 분석하면서, 이 문제에서는 스택 없이도 카운트 방식으로 해결할 수 있다는 점과 또한 사전 조건 검사, 조기 실패 처리, 로직 분리와 같은 요소를 추가한 코드를 봄으로써 같은 알고리즘이라도 **더 안정적이고 읽기 쉬운 코드로 개선할 수 있는 방향을 계속 고민해 볼 수 있었습니다.**

결과적으로 이번 문제는 단순히 하나의 정답을 도출하는 데서 끝나는 것이 아니라, 자료구조 선택의 이유를 설명하고 다른 풀이와 비교하며 **자신의 코드를 객관적으로 점검하는 연습 과정 중 하나가 되었습니다.**

앞으로 문제를 풀 때에도 정답 여부에만 집중하기보다는 “왜 이 방식을 선택했는지”, “어떤 부분을 단순화하거나 개선할 수 있는지”를 함께 고민하는 흐름을 **지속적으로 유지하려고 합니다.**
