**2.문제 해결 과정**

![Image](https://github.com/user-attachments/assets/19cf57fc-f01e-4b25-ba88-f178562800bc)

문제의 풀이는 위의 사진과 같습니다. 우선 주어진 입력값은 1부터 n까지의 수인 n, 그리고 순서대로 k번째의 사람을 없애는 k이고 k는 n보다 클 수 없다는 것이 조건입니다. 

다음으로는 이 문제를 풀기 위해 필요한 자료구조입니다. 선택한 자료구조는 큐입니다. 이유는 순환하면서 k번째 요소를 제거하는 구조이기에 FIFO 특성을 가진 큐를 선택했습니다. poll()로 앞에서 꺼내고 add()로 뒤로 보내는 방식으로 순환을 자연스럽게 표현할 수 있습니다. 

사진에서 보다시피 로직의 순서는 간단합니다. 

1.1부터 n만큼 반복문을 돌려서 큐에 넣는다.
2.while문 안에서 반복문을 돌리면서 k-1만큼의 숫자를 큐를 사용해서 뒤로 보내고 해당k의 숫자를 뺀다.
3.결과값을 출력한다. 

위의 사고 과정을 토대로 해서 작성을 한 코드입니다.

```
	public static void main(String[]args) throws Exception {
		
		BufferedReader br = new BufferedReader(new InputStreamReader(System.in));
		StringTokenizer st = new StringTokenizer(br.readLine());
		StringBuilder sb = new StringBuilder();
		Queue<Integer>queue = new LinkedList<>();
		
		int n = Integer.parseInt(st.nextToken());
		int k = Integer.parseInt(st.nextToken());
		
		// 1부터 n까지 큐에 넣기
		for(int i= 1; i<=n;i++) {
			queue.add(i);
		}
		
		sb.append("<");
		while(!queue.isEmpty()) {
			for(int i =1; i<k;i++) {
				queue.add(queue.poll());
			}
			
			sb.append(queue.poll());
			
			if(!queue.isEmpty()) {
				sb.append(", ");
			}
		}
		sb.append(">");
		
		System.out.println(sb);
	}
```

**3.타인 코드 분석 및 리팩토링**

다음으로는 타인이 제출한 코드 중에서 다수가 푼 문제를 본 결과 유형은 아래와 같았습니다.

- 리스트를 사용해서 인덱스를 조절한 풀이
- 원형 큐를 사용한 풀이

3-1.리스트를 사용한 풀이법

<img width="911" height="817" alt="Image" src="https://github.com/user-attachments/assets/8b0ad458-4823-45e7-ae97-a0ab190ba428" />

제출한 타인의 코드에서 가장 많이 볼 수 있었던 유형이었습니다. 위 코드에서 핵심적인 부분은 

```
int index = 0; 

while (true) { 
	index = (index + k - 1) % list.size(); 
	int num = list.remove(index); 
	... 
}
```

입니다. 이 부분에서 `(index + k - 1) % list.size()` 이 코드가 현재 위치에서 k-1만큼 앞으로 가고, list 크기로 나머지 연산해서 순환시킵니다. 큐처럼 k-1번 반복 안 해도 되고, 인덱스를 바로 계산해버리는 장점이 있습니다.

예를 들면 n=7, k=3이면

- index = (0 + 2) % 7 = **2** → 3 제거
- index = (2 + 2) % 6 = **4** → 6 제거
- index = (4 + 2) % 5 = **1** → 2 제거

코드가 가장 짧고 이해하기 쉽지만, `list.remove(index)`가 O(N)이라는 단점이 있습니다.

3-2.원형큐를 사용한 풀이법

<img width="926" height="912" alt="Image" src="https://github.com/user-attachments/assets/e5e1a8e9-022b-4e13-994b-4b69d2ebba5f" />

이 문제는 자료구조에서 원형큐를 사용해서 푼 방식입니다. 

```
prev=new int[N+1]; 
node=new int[N+1]; 
next=new int[N+1]; 

for(int i=1;i<=N;i++) { 
	prev[i]=i-1; // 1의 이전=0, 2의 이전=1, 3의 이전=2 
	node[i]=i; // 1번 노드=1, 2번 노드=2 
	next[i]=i+1; // 1의 다음=2, 2의 다음=3 
}
```

배열 3개를 선언을 하고 반복문을 통해서 연결 리스트를 만드는 과정입니다.  

예를 들어서 N이 5인 경우라면 아래와 같이 배열의 인덱스를 잡습니다. 

index: 1 2 3 4 5 
prev: 0 1 2 3 4 
node: 1 2 3 4 5 
next: 2 3 4 5 6

다음으로는 배열간의 구조가 원형으로 연결이 되기에 

```
prev[1]=N;   // 1의 이전 = 5 (맨 앞이 맨 뒤를 바라봄)
next[N]=1;   // 5의 다음 = 1 (맨 뒤가 맨 앞을 바라봄)
```

이렇게 하면

```
1 ↔ 2 ↔ 3 ↔ 4 ↔ 5
↑_____________________↑
```

원형 구조가 완성이 됩니다.


다음은 원형 연결 리스트가 완성이 되었으니 메인 루프 부분입니다. 

```
int x=1; // 시작점 

for(int i=0;i<N;i++) { 
	int nxt = find(x, K); // x에서 K번째 노드 
	int tmp = find(nxt, 2); // 제거 후 다음 시작점 
	
	if(i!=N-1) { 
		sb.append(nxt).append(',').append(' '); 
	} else { 
		sb.append(nxt); // 마지막은 쉼표 없음 
	} 
	remove(nxt); // nxt 노드 제거 
	x=tmp; // 다음 시작점으로 이동 
}
```

이 부분에서의 핵심 부분은 `find(nxt, 2)`를 **remove 전에** 하는 것입니다. 이유는 remove 하고 나면 nxt의 next 링크가 끊기기 때문입니다. 그후 미리 다음 시작점을 구해둘 수 있기 때문입니다.

다음은 **find 함수**입니다.

```
private static int find(int x, int k2) {
    if(k2==1) return x;          // k2가 1이면 현재 위치 반환
    return find(next[x], k2-1);  // 아니면 다음 노드로 이동하며 재귀
}
```

find 함수는 x에서 시작해서 next를 타고 재귀로 k2번째 노드를 찾는 함수입니다. 예를 들어 k=3, x=1이면

```
find(1, 3)
→ find(next[1]=2, 2)
→ find(next[2]=3, 1)
→ return 3  ← 3번째 노드
```

k2가 1이 될 때까지 next를 타고 이동하다가 1이 되면 현재 위치를 반환합니다. 재귀 호출이기 때문에 k가 클수록 스택이 깊어지는 단점이 있습니다.

**remove 함수**

```
private static void remove(int now) {
    int pX=prev[now];  // now의 이전 노드
    int nX=next[now];  // now의 다음 노드
    next[pX]=nX;       // 이전 노드의 next를 now 다음으로 연결
    prev[nX]=pX;       // 다음 노드의 prev를 now 이전으로 연결
}
```

remove 함수는 노드를 실제로 삭제하는 것이 아니라 **링크만 끊어버리는 방식**입니다.
예를 들어 3을 제거한다면

```
전: 2 ↔ 3 ↔ 4
후: 2 ↔ 4
   (3은 링크에서 끊김)
```

이 방식의 장점은 삭제가 **O(1)**이라는 점입니다. ArrayList의 `remove()`는 삭제 후 뒤의 원소를 한 칸씩 앞으로 밀어야 해서 O(N)이지만, 링크만 바꾸면 되기 때문에 훨씬 효율적입니다.

**4. 소감**

처음 이 문제를 접했을 때 태그를 통해 힌트를 얻은 상태에서 풀었습니다. 문제를 읽어보니 큐와 배열로 접근하는 것이 적합하다고 판단했고, 배열은 로직이 복잡해질 것 같아 큐를 선택했습니다.

타인의 코드를 분석하면서 예상외의 접근 방식을 발견했습니다. 큐 대신 리스트로 인덱스를 직접 계산해서 푼 방식이 인상적이었고, 특히 원형 연결리스트를 배열로 직접 구현해서 풀어낸 코드는 자료구조에 대한 깊은 이해 없이는 나오기 어려운 풀이라고 느꼈습니다.

이 문제는 큐를 활용한 대표적인 기본 문제인 만큼, 구조를 확실히 익히고 다음에는 응용 문제에서도 활용할 수 있도록 연습할 계획입니다. 또한 리스트, 원형 연결리스트 등 다양한 방식으로도 풀어보며 자료구조 활용 능력을 높여갈 생각입니다.
