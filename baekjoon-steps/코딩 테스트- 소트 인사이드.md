2.문제해결 과정

문제의 요구 사항은 굉장히 단순했다. 입력 받은 숫자를 뒤집어서 출력을 하면 된다. 바로 떠오른 방법은 입력 값을 정수 타입이 아닌 문자열 타입으로 받아서 Char타입의 배열로 전환을 한 다음에 반복문을 돌리면서 출력을 하는 방식을 떠올렸습니다.

2-1. 왜 정수 타입이 아닌 문자열을 택했는가?

- 문제의 요구 사항을 다시 한번 보면 정수의 '자릿수'를 역순으로 재정렬을 하라는 것입니다.
- 만약에 정수 타입을 받아서 자릿수를 쪼갠다면 해당 정수를 10진수로 나눠서 다시 배열에 담아야 한다는 번거로움이 있기에 문자열 타입을 선택을 하게 되었습니다.

2-2. 입력 값의 빅오 표기 해석.

- 요구 사항에서의 자릿수 범위는 N ≤ 1,000,000,000 이고 **수의 크기 자체는 매우 크지만 자릿수의 개수는 최대 10자리**로 제한된다는 것을 알 수 있습니다. 

2-3. 의사 코드 및 흐름도

```
public static void main(String[]args) throw IOException {
	BufferedReader br = new BufferedReader(new InputStreamReader(System.in));
	// 숫자 입력
	String input = br.readLine();
	// char배열로 변경
	char[]arr = input.toCharArray();
	char[]result = new char[arr.length];
	// 배열을 오름차순으로 정렬
	Array.sort(arr);
	// 역순으로 배열에 넣기
	for(int i=0;i<arr.length;i++){
		result[i] = arr[arr.length-1-i];
	}
	
	System.out.println(result);
}
```

3.타인의 코드 분석 및 적용

정답을 제출한 후에 다른 사람들이  작성한 코드를 확인을 해봤습니다. **동일한 문제를 어떻게 다르게 해석하고 구현했는지**를 중심으로 분석했습니다. 특히 숫자를 뒤집는 결과보다, **입력 처리 방식·자료구조 선택·정렬 전략의 차이**에 주목했습니다.

3-1. 정수 기반 자릿수 분해 + 직접 정렬

<img width="952" height="847" alt="Image" src="https://github.com/user-attachments/assets/68463443-1587-4779-bf71-e683cf8ca6a5" />

이 코드는 입력값을 문자열이 아닌 **정수(`int`) 타입으로 받은 뒤**, 10진수 연산을 이용해 자릿수를 하나씩 분해하고,  중첩 반복문을 통해 **정렬 로직을 직접 구현**한 방식이다.

###### 동작 흐름

1. 입력값을 `int`로 읽는다.
2. `n % 10` 연산을 통해 마지막 자릿수를 추출한다.
3. `n /= 10`으로 자릿수를 줄이며 반복한다.
4. 추출한 자릿수를 `List<Integer>`에 저장한다.
5. 중첩 반복문을 사용해 **선택 정렬 방식으로 오름차순 정렬**한다.
6. 정렬된 결과를 역순으로 출력한다.

이 방식의 특징은 다음으로 볼 수 있습니다. 

- **입력 해석 관점**  
  숫자를 수학적 대상(정수)으로 보고, 10진수 연산을 통해 문제를 해결하려는 접근이다.
- **정렬 전략**  
  `Collections.sort()`와 같은 라이브러리를 사용하지 않고 선택 정렬을 직접 구현함으로써 정렬 과정이 코드에 명시적으로 드러난다.
- **시간 복잡도**  
  자릿수 개수를 N이라 할 때, 정렬 단계에서 O(N²)의 시간 복잡도를 가진다.

이 방식은 알고리즘 학습 관점에서는 의미가 있지만, 문제의 핵심인 “자릿수 정렬”보다 **정렬 구현 자체가 더 부각되는 구조**라는 인상을 받았습니다.

3-2. Collection 기반의 정렬 방식

<img width="1002" height="702" alt="Image" src="https://github.com/user-attachments/assets/6553fa69-e947-4a8e-bdb5-84400950b702" />

<img width="1003" height="633" alt="Image" src="https://github.com/user-attachments/assets/8619b5ce-5420-4259-ae0f-54a8d84da6b6" />

공통 흐름은 다음과 같다.

1. 입력을 문자열로 받는다.
2. 문자열을 자릿수 단위로 분해한다.
3. 자릿수를 `List<Integer>`에 저장한다.
4. `Collections.sort()` 또는 `reverseOrder()`를 사용해 내림차순 정렬한다.
5. 정렬된 결과를 순서대로 출력한다.
    

즉, 두 코드 모두 **정렬 로직을 직접 구현하지 않고, 표준 라이브러리에 위임**하는 접근이다. 이 점에서 알고리즘 구현보다는 **문제 해석과 코드 간결성**을 우선한 방식이라고 볼 수 있다.

겉으로 보면 큰 흐름에서는 동일해 보이지만, 두 코드에는 **명확한 차이점**이 존재합니다.

##### (1) 자릿수 분해 방식의 차이

첫 번째 이미지에 있는 코드는 다음 방식을 사용합니다.

`Character.getNumericValue(number)`

- 의미가 명확하고 안전한 변환 방식
- 문자 → 숫자 변환의 의도가 코드에 그대로 드러남

두 번째 이미지의 코드는 다음 방식을 사용합니다.

`c - '0'`

- ASCII 값을 이용한 값 변환

 **둘 다 결과는 동일하지만**,

- 하나는 가독성 중심이고 
- 다른 하나는 _구현 비용과 속도 중심_ 선택입니다.
###### (2) 입력 파싱 방식의 차이

- 한 코드는 `toCharArray()`를 사용
- 다른 코드는 `charAt(idx)`를 반복 호출

이 차이는 성능보다는 **코딩 스타일과 사고 흐름의 차이**에 가깝습니다.

- `toCharArray()` → 문자열을 배열로 보고 처리
- `charAt()` → 문자열을 순차 접근 대상으로 처리

###### (3) 출력 처리 방식의 차이

- 한 코드는 `StringBuilder`에 누적 후 한 번에 출력
- 다른 코드는 `System.out.print()`를 반복 호출

이 문제의 출력량에서는 큰 성능 차이는 없지만, 일반적으로는 **StringBuilder 방식이 확장성과 안정성 측면에서 유리**합니다.

3-3. 문자열 split + 반복 비교 방식

<img width="1010" height="795" alt="Image" src="https://github.com/user-attachments/assets/786d9e5b-ba48-4e87-b180-cb5db2747948" />

다음 코드는 입력값을 문자열로 받은 뒤 `split("")`을 사용해 각 자릿수를 문자열 배열로 분리하고, 중첩 반복문을 통해 최대값을 선택하는 방식이다.

###### 동작 흐름

1. 입력값을 문자열로 읽는다.
2. `split("")`을 통해 자릿수를 문자열 배열로 분해한다.
3. 반복문을 통해 현재 범위에서 가장 큰 값을 찾는다.
4. 선택된 최대값을 결과 문자열에 누적한다.
5. 사용한 값은 배열 내에서 교체 처리한다.
6. 위 과정을 배열 길이만큼 반복한다.

이 방식은 **정렬 API를 사용하지 않고**, 반복 비교를 통해 결과를 만들어낸다는 점이 특징입니다.
###### 특징 및 분석

- **입력 해석 관점**  
  숫자를 정수나 컬렉션이 아닌 **문자열 집합**으로 바라봅니다.
- **정렬 전략**  
  정렬 알고리즘을 사용하지 않고, 매 단계마다 최대값을 선택하는 방식으로 결과를 구성합니다.
- **시간 복잡도**  
  자릿수 개수를 N이라 할 때, 중첩 반복문으로 인해 O(N²)의 시간 복잡도를 가집니다.

3-5. 카운팅 배열 기반 처리 방식

<img width="973" height="588" alt="Image" src="https://github.com/user-attachments/assets/fb3614d0-6428-4b39-bc10-d559c5240acd" />

마지막 코드는 앞선 코드들과 달리 정렬이나 Collection을 사용하지 않고, **숫자 범위의 특성을 활용한 카운팅 방식**으로 문제를 해결합니다.

##### 동작 흐름

1. 입력을 한 글자씩 읽는다.
2. 각 자릿수에 대해 `0~9` 범위의 배열(`int[10]`)에 빈도를 기록한다.
3. 배열의 인덱스를 `9 → 0` 역순으로 순회한다.
4. 빈도 수만큼 해당 숫자를 출력한다.

즉, **자릿수의 등장 횟수만 기록한 뒤 역순으로 출력**하는 방식이다.

###### 특징 및 분석

- **입력 해석 관점**  
  숫자를 “정렬 대상”이 아니라 **제한된 범위를 가진 데이터(0~9)**로 해석합니다.
- **정렬 전략**  
   비교 기반 정렬이 아닌 **카운팅 정렬(Counting Sort)의 아이디어를 직접 적용**한 방식입니다.
- **시간 복잡도**  
  자릿수 개수를 N이라 할 때 전체 로직은 O(N)으로 동작합니다.

###### 3-6. 차이점과 공통점을 통해 본 내 코드의 선택 이유

타인의 코드들을 분석하면서 공통적으로 확인한 점은, 풀이가 결국 **자릿수를 분해한 뒤 정렬 또는 비교를 통해 재배치**한다는 것이다. 이는 문제를 “자릿수 단위 처리 문제”로 해석했다는 점에서 동일하다. 반면, 접근 방식에는 분명한 차이가 있었습니다.

- 정수 기반 풀이는 자릿수 분해와 정렬을 모두 직접 구현하며 알고리즘 학습에 초점을 둔 방식
- Collection 기반 풀이는 표준 라이브러리를 활용해 문제의 의도를 간결하게 표현하는 데 집중하는 방식
- `split()` 기반 풀이는 절차적 비교를 통해 결과를 구성했지만 가독성과 확장성 측면에서는 아쉬움이 남았다.
- 카운팅 배열 방식은 조건을 적극 활용한 최적화된 해법이었으나, 문제 일반화에는 한계가 있었다.

이러한 공통점과 차이점을 바탕으로, 저는 **문제의 핵심 의도가 코드 구조에서 바로 드러나는 방식**을 선택했습니다.

문자열 기반으로 자릿수를 처리하고, 불필요한 자료구조 변환이나 정렬 구현을 배제한 채  
`Arrays.sort()`와 역순 출력이라는 단순한 흐름으로 구성함으로써, 타인이 코드를 읽을 때 해결 전략을 빠르게 파악할 수 있고 문제 요구사항과 코드 구조가 자연스럽게 연결되며 리뷰 상황에서도 선택의 근거를 설명하기 쉬운 구현을 목표로 했습니다. 

3-7. 코드 분석을 토대로 한 개선된 코드

```
import java.io.*;
import java.util.Arrays;

public class Main {
    public static void main(String[] args) throws IOException {
        BufferedReader br = new BufferedReader(new InputStreamReader(System.in));

        // 입력을 문자열로 받아 자릿수 단위로 처리
        char[] digits = br.readLine().toCharArray();

        // 자릿수 정렬 (문제 의도: 자릿수 재정렬)
        Arrays.sort(digits);

        // 역순 출력 (내림차순)
        StringBuilder sb = new StringBuilder(digits.length);
        for (int i = digits.length - 1; i >= 0; i--) {
            sb.append(digits[i]);
        }

        System.out.print(sb);
    }
}
```

위 코드는 타인 코드 분석을 통해 정리한 기준을 바탕으로, 문제의 핵심 의도가 코드 구조에서 바로 드러나도록 재구성한 코드입니다. 성능 최적화보다는 가독성과 설명 가능성을 우선했으며, 리뷰 상황에서도 선택의 근거를 명확히 전달하는 것을 목표로 했습니다.  제출후 결과는 아래와 같습니다.

4.소감

이번 문제를 통해 단순히 정답을 맞히는 것보다, **다른 사람들의 코드를 분석하고 비교하는 과정 자체가 훨씬 중요하다는 점**을 체감했다.

같은 문제라도

- 정수 기반으로 자릿수를 분해해 직접 정렬하는 방식
- Collection을 활용해 정렬을 위임하는 방식
- `split()`을 사용해 절차적으로 최대값을 선택하는 방식
- 숫자 범위를 활용한 카운팅 배열 방식까지 접근 관점과 구현 전략이 크게 달랐다.

이 과정을 통해 코드를 볼 때 “이게 맞다 / 틀리다”가 아니라, **왜 이런 선택을 했는지, 무엇을 우선했는지**를 먼저 보게 되었다.

특히 타인의 코드와 비교하면서 내 코드가 문제의 요구 사항을 얼마나 직접적으로 드러내는지, 그리고 리뷰나 협업 상황에서 **설명 가능한 구조를 가지고 있는지**를 점검할 수 있었다는 점이 의미 있었다.

이번 정리는 단순한 코딩 연습이 아니라, **타인의 코드를 읽고 판단하며, 그 기준 위에서 내 선택을 설명하는 훈련**이었다. 앞으로도 문제를 풀 때 정답에만 집중하기보다는 
이와 같은 비교·분석 과정을 통해 코드 리딩과 설계 관점을 함께 키워가고자 한다.
